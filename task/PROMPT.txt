为代码审查团队实现一个针对简化 Python 子集的注入风险分析器，输入是本地源文件，禁止执行被审查代码。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 支持函数调用、返回值、局部变量、字典常量键读写、if/else 与有界递归摘要；request() 是污染源，sql_exec() 是汇。未知函数保守传播污染，但必须区分安全、危险、无法判定三类。待分析子集不含循环、类、闭包和动态导入；不支持语法返回无法判定。
2. sql_quote 只保证作为 SQL 字符串字面量的安全性，不保证标识符安全；同一净化结果经过拼接、覆盖或作为列名使用时要按上下文判定。对布尔等值条件保留相关性，不能把互斥分支拼成虚假的可达攻击路径。汇调用约定为sql_exec(kind,parts)，kind只为literal或identifier，parts是字符串片段列表；literal上下文要求所有污染片段均经sql_quote处理，净化后再拼入污染片段仍为危险。
3. 输出源到汇的文件行列、调用链与条件证据；递归求不动点并有终止保证。实现摘要缓存，修改被调用函数后必须使相关调用者失效，未受影响模块应复用缓存。

必须覆盖的验收场景：包含两个分支单独安全但错误合流会误报、别名覆盖造成漏报、递归环、净化器上下文误用和增量修改；用全量重算核对增量结果。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
